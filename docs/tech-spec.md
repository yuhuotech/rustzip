# 技术规范

本文件是写代码时必须遵守的约束。架构见 `architecture.md`,界面见 `ui-spec.md`。

## 1. 语言与工具链

- Rust stable,在 `rust-toolchain.toml` 中固定版本;edition 2021 起步,跟随稳定版升级。
- Cargo workspace,依赖版本统一放在根 `Cargo.toml` 的 `[workspace.dependencies]`。
- 提交前必须通过:`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`。
- 依赖审计用 `cargo deny`(许可证与漏洞)。

## 2. 许可证

- 项目许可证:`MIT OR Apache-2.0`。
- 引入依赖前先检查许可证,**禁止引入 GPL / AGPL / LGPL 的静态链接依赖**。
- **不拷贝 7-Zip 源码**(LGPL)。参考其格式规范,自行实现。
- RAR:仅通过 `rz-ffi` 的 `unrar_sys` 调用 unRAR 做只读解压,放在独立 Cargo feature `rar` 下,发行包附带 unRAR 授权声明;不实现任何 RAR 压缩。
- libarchive(BSD)可直接使用。

## 3. 代码规范

- 库代码(`crates/*`)**禁止 `unwrap()` / `expect()` / `panic!` 处理可恢复错误**,一律返回 `Result`。测试和确实不可能失败且有注释说明的地方除外。
- 错误类型:库用 `thiserror` 定义结构化错误,应用层可用 `anyhow`。错误信息要能让用户理解发生了什么、怎么办。
- `unsafe` 默认禁止(`#![forbid(unsafe_code)]`);确需使用的 crate(如 FFI、mmap)单独标注,每处 `unsafe` 必须有 `// SAFETY:` 注释。
- 所有耗时操作必须支持**取消**和**进度回调**(`rz-core` 的取消 token)。
- 公开 API 写文档注释;命名遵循 Rust 惯例;模块职责单一。
- 注释只解释"为什么",不复述代码。
- 不引入不必要的依赖;新增依赖要说明理由。

## 4. 性能规范

- 热路径禁止多余的内存拷贝和分配;不整体缓冲文件,按块流式处理。
- 线程数、字典大小、内存占用受全局内存预算约束。
- 新增或修改压缩 / 解压路径时,必须跑 `benches/` 并确认没有回归。
- GUI 线程只做渲染和事件分发,**任何 I/O 和计算都不得阻塞 UI 线程**。
- 大列表必须虚拟化;进度事件合并后再推送(建议不高于 30 次/秒)。
- 冷启动目标:GUI 小于 300ms 出现窗口;右键菜单操作小于 200ms 开始响应(指标以实测基线为准,持续跟踪)。

## 5. 安全规范

- 解压必须经过路径规范化检查:拒绝 `..`、绝对路径、盘符、会逃出目标目录的符号链接。
- 必须有压缩炸弹防护:压缩比、总大小、嵌套深度上限,默认值保守且可在设置中调整。
- 所有来自压缩包的数据都是不可信输入:长度、偏移、条目数先校验再使用,防止整数溢出和越界。
- 密码和密钥用 `zeroize` 清理;日志中**不得**出现密码、文件内容、完整用户路径。
- 删除源文件(压缩后删除)必须在压缩包校验通过后才执行。
- 更新包必须验签,验签失败拒绝安装。

## 6. 测试规范

- 单元测试放在模块内,集成测试放在 `tests/`。
- 每种格式必须有:往返测试(压缩再解压内容一致)、损坏文件测试、加密测试、边界测试(空文件、超长文件名、中日韩文件名、符号链接)。
- **交叉验证**:与 7-Zip、libarchive 互相压缩、互相解压的矩阵测试。
- 所有解析器配套 `cargo-fuzz` 目标。
- CI 三平台矩阵(Windows、macOS、Linux)必须全部通过。
- 修 bug 时先写能复现的测试。

## 7. 平台兼容规范

- 最低支持:Windows 10、macOS 12、主流 Linux 发行版(以 glibc 2.28 为基线,需随验证结果确认)。
- 路径一律用 `Path` / `PathBuf` 和 `rz-platform` 提供的工具,不手拼分隔符。
- 文件名编码、大小写敏感性、Windows 保留名、长路径差异在 `rz-platform` 统一处理。
- 平台特有代码用 `cfg` 隔离在 `rz-platform` 和 `apps/shell-ext`,核心 crate 保持平台无关。

## 8. 提交规范

- 提交信息简短清晰,说明改了什么和为什么。
- 小步提交,一次提交只做一件事。
- 不提交构建产物、密钥、本地配置。
