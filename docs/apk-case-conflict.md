# APK 解压大小写冲突

## 已确认的原因

本机 `FlClash-0.9.0-android-arm64-v8a.apk` 共 433 个条目，全部 CRC 检查通过。四组文件名仅大小写不同，内容并不相同：

- `res/9N.9.png` / `res/9n.9.png`（187 / 178 字节）
- `res/Gt.9.png` / `res/gt.9.png`
- `res/QZ.xml` / `res/qz.xml`
- `res/YG.9.png` / `res/yg.9.png`

Downloads 所在卷经临时探针确认不区分大小写。两个不同 ZIP 条目映射到同一磁盘路径，默认“不覆盖”策略的 `create_new` 在第二个条目触发 AlreadyExists。旧代码仅报告完整目标路径，遗漏文件已存在的原因，且发现冲突前已写入部分文件。

## 修复

- 在默认安全策略下，解压预检发现大小写候选冲突后才探测目标目录所在卷。使用独占临时目录探测并清理，不创建解压目标目录；没有候选冲突的常见压缩包不额外探测。
- 不区分大小写的卷在写入前返回结构化 NameConflict，只携带压缩包内的两个名称。区分大小写的卷继续原样解压两个文件。
- GUI 任务和状态栏使用中英文资源说明原因及解决办法；普通目标已存在时也有明确提示，不再把完整用户目标路径作为错误内容。
- 显式 Skip / Replace 的策略保留；不自动覆盖、改名或改动 APK。需要完整保留资源应使用区分大小写的 APFS 卷/磁盘映像，或其他区分大小写的文件系统。
- `rz-platform` 的直接 `tempfile` 依赖用于同卷独占探针，版本沿用 workspace，许可证 MIT OR Apache-2.0；原先已经是该 crate 的测试依赖。

## 验证

- 先新增与 APK 一致的最小重现：旧代码测试失败，因为目标目录已经部分写入。
- 修复后最小重现通过；平台探针验证包含清理和不创建目标目录。
- GUI 回归验证任务错误码、中文原因、两个相对名称、英文解决提示及不泄露完整目标路径。
- 真实 APK 在 Downloads 所在不区分大小写卷上，修复后 CLI 返回上述两个相对名称的冲突原因；未创建解压目录，无残留探针。
- 创建临时 512 MiB 区分大小写 APFS 映像，真实 APK 的 433 个文件全部解压成功；每个文件与 ZIP 内原始数据的 SHA-256 一致，两份大小写不同资源的 inode 不同。测试后映像已卸载并删除。
- `cargo fmt --check`、全 workspace / all-targets / all-features Clippy（`-D warnings`）及全 feature 测试通过；GUI 共 45 项，解压往返共 26 项。真实钥匙串测试按现有配置跳过，Windows / Linux 实机未运行。
- `RZ_BENCH_MB=8 cargo bench -p rz-engine --bench throughput` 已运行：ZIP 单线程解压 1307 MB/s、并行 3437 MB/s，处于本机既有采样范围；无冲突归档不会增加卷探针 I/O。此冒烟结果不能替代固定负载下的重复性能测量。
