# 左侧菜单功能实现计划

## 设计

- 常用位置：已按后续确认方案改为系统默认目录 + 自动记录压缩包所在目录，并支持列表/小图标浏览；旧收藏保留。详见 `locations-redesign.md`。
- 密码本：系统钥匙串中新增、编辑、删除命名密码；列表不读取或显示明文；编辑时才在后台读取。保存失败保留表单并提示，不虚报成功。
- 转换格式：选择源包和目标格式、输入源密码和可选目标密码；ZIP / tar / 7z 源文件内容流式转换，不解压到文件夹。单文件压缩流沿用现有后端先测量大小再转换的两遍读取，测量阶段也支持取消和总量限制；可选 RAR 后端沿用 unRAR 的逐条临时落盘。校验输出后原子另存，拒绝覆盖已有文件。RAR 只能作为读取源。
- 修复：ZIP 从仍可读条目恢复，中央目录不可用时扫描本地文件头；7z 恢复仍可解码的条目，头部或固实块严重损坏可能无法继续。逐条校验后写入新包；明确显示恢复数、跳过数和原因，不承诺恢复损坏内容。
- 两类长任务复用后台任务队列、暂停、取消和进度；输出发布前校验，失败或取消清理临时文件，源包不变。
- 当前写入接口无法保留符号链接，转换遇到链接明确拒绝，修复明确记录跳过。ZIP 中央目录丢失后，本地头没有权限和链接类型信息，无法识别的链接会按普通文件恢复；报告对此明确警告。
- 新文案放中英文资源文件；页面使用既有颜色令牌、紧凑布局及可滚动列表。

## 阶段与验收

1. 应用/引擎/格式层：收藏设置、流式转换、安全恢复、任务队列及有意义的损坏/取消/安全/往返测试。
2. GUI：四项入口、收藏和密码管理、转换/修复表单、恢复报告、键盘入口。
3. 文档、fmt、clippy、测试、基准和本机界面验证；如实记录跨平台未验部分。

## 依赖与验证方式

- `tempfile`：同目录的独占临时输出、原子拒绝覆盖发布、逐条恢复的临时数据；MIT OR Apache-2.0。
- `zeroize`：新转换任务的密码选项在释放时清理，内存密码库、钥匙串回滚临时副本和 GUI 后台读写密码的临时副本使用 Zeroizing；Apache-2.0 OR MIT。GUI Kit 输入框内部的存储由框架管理，不能承诺对框架持有的每份文本副本都做内存擦除。
- `libfuzzer-sys`：仅用于独立 fuzz workspace，不进入产品依赖；(MIT OR Apache-2.0) AND NCSA。
- ZIP 本地头恢复 fuzz：`cargo +nightly fuzz run zip_recovery -- -runs=1000`（在 `fuzz/` 目录，需先安装 cargo-fuzz）。加密、数据描述符及 ZIP64 条目在目录丢失时可能无法恢复，会记入报告；不会猜测数据边界后伪造成功。

## 性能记录（macOS，本机冒烟）

- 修改前 `HEAD` 的独立源码副本与本次代码分别运行 `throughput`，输入为 8 MiB 和 32 MiB。原压缩/解压算法未改；本机受后台负载和缓存影响，ZIP 并行解压波动较大（约 2.5–3.8 GB/s），不能据单次冒烟宣称严格无回归。
- 新增转换基准含输出完整性校验。8 MiB 样本：ZIP→ZIP 72 MB/s，ZIP→7z 4 MB/s，ZIP→tar.zst 146 MB/s，ZIP 恢复→ZIP 68 MB/s；这些是本机样本结果，不是产品性能保证。7z 流式逐条写入会形成独立块，压缩率和整体固实压缩不同。
- 复现：`RZ_BENCH_MB=8 cargo bench -p rz-engine --bench throughput`；常规 CI 使用 32 MiB，正式性能结论应在固定负载、多次采样条件下评估。
