# 开发计划与第一阶段验收

计划日期：2026-10-28。以当前工作区为基础，不覆盖已有改动。

## 总体顺序

1. **稳定性收口**：验证当前核心改动、限制预览资源、建立可复现基线，并完成本机回归。
2. **三平台验收**：Windows 原生构建、输入法、渲染、钥匙串、通知、菜单和安装器；macOS 的钥匙串、通知、文件关联及公证；Linux Dolphin / Nemo。每个平台保留环境和逐项验收证据。
3. **基础格式与互通**：评估 WIM、DMG、CHM、NSIS 的许可证和安全后端，补足只读能力及识别；扩大分卷、加密、Unicode、损坏输入与外部工具的互通矩阵。2026-10-29 已完成候选审查并安全接入 CHM 只读浏览 / 提取；WIM、DMG 保持签名识别和明确不支持，NSIS 不按普通 `.exe` 推断。证据见[第三阶段记录](phase-3-format-assessment.md)。RAR 保持只读。
4. **体验完善**：评估安全的 PDF / 音视频预览、ZIP 编辑元数据与增量能力，完成屏幕阅读器、RTL 和键盘操作验收。
5. **发布闭环**：完善自动 CI、fuzz 和样本；演练签名、更新安装和三平台发布；核验官网与统计服务。挂载、云读取、插件、SFX 等远期功能另行评估。

阶段依赖按上述顺序处理；涉及平台设备、正式签名或生产部署时，必须有相应实测证据才能标记通过。

## 第一阶段范围

本阶段不包含跨平台实机验收或新增长尾格式。

## 工作与验收

1. 复核 7z 并行解压、bzip2 并行压缩和 ZIP 编辑的数据安全、取消、失败恢复与回退路径；补充有实际覆盖价值的回归测试。
2. 验证顺序格式预览的限额、损坏数据及密码边界；对于无法保证临时磁盘有硬上限的 RAR 预览，阻止不受限的预览读取并向用户说明如何打开内容。
3. 复核更新安装器交接的后台执行和失败处理，补充可自动验证的用例。
4. 在同一机器上多次运行不同大小的压缩 / 解压基准，以及 ZIP 编辑优化和重打包对照；记录命令、样本、结果、校验范围和局限，不以单次结果推断普遍性能。
5. 运行格式检查、全工作区 all-features Clippy 和测试；运行压缩 / 解压基准。同步 README、架构和决策记录，并如实记录未覆盖范围。

- 压缩 / 解压基准及 ZIP 编辑对照完成，结果和原始数据见下文。第一阶段约定的本机开发与验证已完成；三平台实机、真实安装器、持续 fuzz 和大规模性能验收仍在后续范围。

## 本机性能记录

- 环境：Apple M5 Pro，15 个逻辑 CPU，48 GiB 内存，macOS arm64，Rust 1.96.0。
- 对照：旧提交 `7bcd980` 的独立源码快照与当前工作区各自使用独立 Cargo target；交替运行，每组 3 次。8 / 32 MiB 的输入分别为 8 / 32 个 1 MiB 可压缩文本文件。详细输出和 `/usr/bin/time -l` 数据保存在 [原始结果](benchmarks/2026-10-28-phase1-raw.txt)。
- 旧版吞吐基准检查所有文件长度及首个文件内容；当前版加强为逐文件内容比较。ZIP 编辑基准比较优化和重打包后的全部文件 SHA-256。
- 复现：在旧提交快照与当前工作区分别使用独立的 `CARGO_TARGET_DIR`，运行 `RZ_BENCH_MB=8 cargo bench -p rz-engine --bench throughput`，将 8 换为 32 并各重复三次；当前工作区运行 `RZ_BENCH_MB=8 cargo bench -p rz-app --bench zip_edit`，再换成 32 / 128，各重复三次。应交替运行对照，避免其他编译和测试同时占用机器。

下表是三次吞吐量的中位数，单位 MiB/s；旧版 / 当前版按相同输入和线程数比较。

| 样本 | 场景 | 压缩：旧 / 新 | 解压：旧 / 新 |
|---|---|---:|---:|
| 8 MiB | ZIP，单线程 | 80 / 79 | 1444 / 1447 |
| 8 MiB | ZIP，15 线程 | 425 / 414 | 3592 / 3509 |
| 32 MiB | ZIP，单线程 | 83 / 83 | 1488 / 1378 |
| 32 MiB | ZIP，15 线程 | 695 / 696 | 3371 / 3628 |
| 8 MiB | 7z level 3，15 线程 | 52 / 53 | 305 / 303 |
| 32 MiB | 7z level 3，15 线程 | 178 / 177 | 969 / 971 |
| 8 MiB | tar.bz2，15 线程 | 22 / 164 | 49 / 53 |
| 32 MiB | tar.bz2，15 线程 | 22 / 235 | 50 / 53 |

当前版独立固实块 7z 的解压中位数：8 MiB 为单线程 231、15 线程 856 MiB/s；32 MiB 为单线程 232、15 线程 1307 MiB/s。旧版基准没有此独立块场景，因此这是当前版内部线程对照。

ZIP 删除编辑的中位数（压缩数据复用 / 完整重打包）：保留 8 MiB 为 0.017 / 0.121 秒，32 MiB 为 0.047 / 0.468 秒，128 MiB 为 0.155 / 1.873 秒。样本为两个使用重复的 1 MiB 伪随机块构造的文件，不代表所有真实文件或操作。

整套吞吐基准的峰值 RSS：8 MiB 旧版约 380 MiB、当前版约 420 MiB；32 MiB 旧版 582–702 MiB、当前版 650–770 MiB。当前套件比旧版多一个 7z 独立块场景，数值是整个进程的峰值，不能归因到单个算法，也不能证明内存预算是进程硬上限。32 MiB ZIP 单线程解压中位数下降约 7%，与其他行一样需结合原始样本和更多设备观察；小样本、三次运行不能证明所有数据集没有性能回归。

## 进一步发现

- 2026-10-30 后续改造已将 UnRAR 数据回调封装进 `rz-ffi`：解码前检查压缩比，所选内容逐块写入限额临时文件，未选内容不落盘；声明大小 / 剩余 `max_total` 超限和取消会在原生回调内中止。RAR 详情预览改为限额内存读取。Release dry-run [41005419057](https://github.com/yuhuotech/rustzip/actions/runs/41005419057) 已验证四平台 RAR 测试包、许可证与 Windows 安装 / 卸载关联；正式签名发布仍待验收。
