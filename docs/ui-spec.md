# UI 规范

视觉稿见 `docs/ui/preview.html`(可直接用浏览器打开,含浏览、新建压缩、任务三个界面和明暗主题)。**实现时以视觉稿为准**,本文件是其文字化的规范。

## 1. 设计风格

**简洁、大气、克制。** 冷灰中性色为底,只有一个青绿强调色,仅用于主操作和选中状态。数字、路径、大小用等宽字体对齐。留白充足,信息层级靠字重和灰度区分,不靠装饰。

原则:
1. 一个强调色,不滥用。
2. 默认只露出常用选项,高级项折叠。
3. 明暗主题都要认真做,默认跟随系统,可手动切换。GPUI Kit 不会自己跟随系统:窗口创建时调用 `Theme::sync_system_appearance`,并监听 `observe_window_appearance` 在系统切换时再次调用(用户选了固定的浅色或深色时则不监听)。
4. 状态用形态表达,而不只靠颜色(图标、文字、进度条)。
5. 界面不得出现卡顿:所有耗时操作在后台,界面始终可操作。

## 2. 色彩令牌

实现时必须用语义令牌,**不得在组件里写死颜色值**。

| 令牌 | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `bg` | 应用背景(窗口外) | `#e9edf1` | `#080c10` |
| `win` | 窗口 / 主内容底 | `#ffffff` | `#11171d` |
| `panel` | 侧栏、标题栏、状态栏 | `#f5f7f9` | `#0d1318` |
| `line` | 分割线、边框 | `#e2e7ec` | `#212b34` |
| `fg` | 主文字 | `#121c26` | `#e7eef4` |
| `fg2` | 次要文字 | `#56677a` | `#98a8b6` |
| `fg3` | 弱化文字、占位 | `#8896a4` | `#64737f` |
| `accent` | 强调色 | `#0d9b82` | `#2fd3a7` |
| `accent-ink` | 强调色上的文字 | `#ffffff` | `#04231b` |
| `accent-soft` | 选中行、强调浅底 | `#dff4ee` | `#11342c` |
| `hover` | 悬停底色 | `#eef2f5` | `#18212a` |
| `warn` | 警告 | `#c98200` | `#e5a62a` |
| `danger` | 危险、删除 | `#d23f3f` | `#ef6b6b` |

语义色(警告、危险)与强调色是两回事,不得混用。

**强调色可配置,默认是石墨。** 上表的青绿值现在是第二个选项"墨绿"。设置里"主色"可选石墨、墨绿、深蓝、紫罗兰、玫红,保存在 `settings.json` 的 `accent` 字段;也可以手写 `"#rrggbb"`(明暗主题共用),写错则回到石墨。换主色只改 `accent`、`accent-soft`、`accent-ink` 三个令牌,组件里不得绕过令牌。除墨绿外,`accent-soft` 由强调色与窗口色混合得出(浅色 12%、深色 20%),`accent-ink` 按亮度取白或近黑。石墨在浅色下近黑(`#2b3640`)、深色下近白(`#e3e9ee`),与应用图标一致,是最克制的选择。

## 3. 字体

- 界面字体**跟随系统**:macOS 苹方、Windows 微软雅黑 UI(或 Segoe UI Variable)、Linux 思源黑体(Noto Sans CJK)。视觉稿用 Geist 仅为预览效果。
- 数字、路径、大小、日期:等宽字体(Geist Mono / SF Mono / Consolas),开启等宽数字,保证列对齐。
- 字号:正文 14、次级 13、辅助 12、小标签 11(大写加字距)、面板标题 18、详情标题 15。
- 字重只用 400 / 500 / 600。
- 必须验证中日韩字体回退和输入法组合输入(见 `decisions.md`)。

## 4. 形状与间距

| 项目 | 值 |
|---|---|
| 窗口圆角 | 14 |
| 卡片、预设卡圆角 | 12 |
| 控件(按钮、输入框)圆角 | 8 |
| 药丸 / 标签 | 全圆角 |
| 文件列表行高 | 38(表头 34) |
| 工具栏内边距 | 10 14 |
| 基本间距单位 | 4 的倍数(4 / 8 / 12 / 16 / 24) |
| 边框 | 1px,颜色 `line` |

阴影只用于浮层和窗口,列表和卡片不加阴影。

## 5. 布局

### 主窗口(浏览)

```
┌ 标题栏:系统原生,显示 RustZIP ───────────────────────────┐
├ 工具栏:[解压到…(主)] 添加 测试 删除 │ 预览 ····· 搜索 ┤
├ 面包屑:↑ 压缩包名 › 文件夹 › 子文件夹 ───────┬ 详情 224 ┤
│ 文件表:名称 | 大小 | 压缩后 | 修改时间         │ 徽章 + 名称 │
│ (虚拟化列表,点击选中,双击进入文件夹)        │ 属性列表   │
│                                              │ [解压此项] │
├ 任务面板(有任务时出现):进度、速度、剩余时间、暂停、取消 ┤
├ 状态栏:条目数 · 体积变化 · 节省比例 ········ 格式 ┤
└────────────────────────────────────────────────┘
```

- **顶部标签栏**(高 38):macOS 上与窗口按钮同一行(标题栏透明,标签栏左侧留 84 留给红黄绿按钮);Windows / Linux 未验证,仍用系统标题栏,标签栏另占一行。打开了压缩包就显示,每个压缩包一个标签(图标、名称、加密标记、×),末尾"+"打开新的压缩包。欢迎页不显示。此前曾取消标签栏,现按视觉稿恢复。
- **左侧栏**(宽 168,窗口宽度 ≥ 560 时显示):每一行都是"图标 + 文字",高 32。"位置"含当前压缩包(选中态)、最近打开(右侧是个数;它是一个菜单项,不在菜单里展开文件,点它后右侧整块区域换成"最近打开"页,列出最近的压缩包,点一行就打开并回到文件页)、常用位置;"快速操作"含转换格式、修复压缩包、密码本。常用位置和快速操作的三项功能尚未开发,按设计稿保留位置,以灰色加"即将推出"显示。
- **详情栏**:顶部 140 高的预览区,圆角 12。图片(png / jpg / gif / webp / bmp,解出不超过 8 MB)直接显示图片本身;其他文件显示对应文件类型颜色的底和大号类型标签;未选任何项时显示压缩包图标和整体信息。往下依次是文件名、类型名(如 JavaScript)、各项信息,最后是带图标的整宽主按钮"解压此项"(未选时是"解压全部")。
- **状态栏**(高 34):左侧依次是校验结果(测试通过后显示"校验通过",失败显示"校验未通过")、条目数、体积变化、"压缩率 N%"药丸(压缩后占原始大小的比例);右侧是格式,加密的压缩包后面加锁图标和"已加密"。设计稿里的压缩算法(如 LZMA2)和"固实"目前读取层没有提供,暂未显示。
- 没有打开任何压缩包时只显示欢迎界面(拖入提示、打开、新建、最近打开),不显示工具栏。
- 默认窗口 900×580,最小 640×420。详情栏宽 224。
- 一个工具栏里只有一个主按钮(强调色填充),即"解压到…":选了项目就解压所选,没选就解压全部。"新建压缩"不在工具栏,走 `⌘N`、菜单和欢迎页。
- **"最近打开"页**:像文件夹里的列表,一行一个压缩包:名称、大小(紧跟名称,是最常看的信息)、位置、创建时间、修改时间,点列标题排序(再点反向,未知值永远排最后,默认修改时间新的在前)。单击选中,双击打开;已被移走的灰显并写"已移走"。文件信息在后台读取,不卡界面。
- **工具栏随当前操作变化**:在"最近打开"页,没选中任何一行时是"打开压缩包… / 新建压缩 / 清空记录";选中一个压缩包后变成针对它的操作:打开、解压到当前文件夹、解压到同名文件夹(单文件格式如 .gz 没有这项)、在文件夹中显示、重命名、删除(移到废纸篓/回收站,可恢复)、从列表移除。文件已被移走时只剩"从列表移除"。状态栏也随页面变:这一页显示"N 个最近的压缩包 · M 个已移走",不再显示打开着的压缩包的信息。
- **右键菜单**(压缩包内的文件列表):对单个或多个选中项都可用。右键点在选中范围外的行,先只选中它;点在选中范围内,保持整个选择,菜单项作用于全部选中项,顶部显示"已选 N 项"。菜单项:打开 / 打开文件夹(只对单个项)、解压到…、解压到当前文件夹(压缩包所在文件夹)、解压到“压缩包名”文件夹、复制路径(每行一个压缩包内路径)、添加文件到此文件夹…(只对单个文件夹)、重命名(只对单个项)、删除。后三项会重写压缩包,格式不支持时置灰,菜单顶部会写明原因("RAR 压缩包只读,不能添加、重命名或删除"),工具栏上对应的按钮悬停时也是这句。是否能改由文件的真实格式决定,不看扩展名:改了名的 zip(.jar、.docx、.apk 等)照样能添加和删除;rar、单文件的 gz / xz 等只读。**右键点在列表的空白处**(行以下的空白):先取消所有选中(详情栏回到压缩包概览),再弹一个很短的菜单:添加文件到此处…(放进当前显示的文件夹,不支持改动的格式置灰)、全选(列表不空时)。这里不放"解压",因为在压缩包或子文件夹的空白处,人最可能想做的是往里面放东西。左键点空白处暂不取消选中。⌘A / Ctrl+A 选中当前文件夹里的全部项目(在搜索框里仍是全选文字)。多选:⌘/Ctrl-点击逐个加减,Shift-点击选一段。
- **提示消失**:操作结果(如测试通过)在状态栏显示 6 秒后自动消失,错误 12 秒;用户一旦换文件夹、换文件、换标签页或换页面,立即消失,状态栏回到描述眼前内容的信息。
- **双击文件**:在压缩包里双击文件,解到系统临时目录并用系统默认程序打开。对 zip、7z、tar 系列,程序保存修改后(文件稳定约 1 秒)会自动写回压缩包,并在状态栏提示;其余格式只读,提示改动不会写回。关闭该压缩包的标签页后不再监视。程序和脚本不会被打开。
- **重命名**:压缩包内的文件或文件夹(同样重写压缩包,名称不能为空、不能含 / \ : * ? " < > |、不能与同级重名),以及最近打开页里的压缩包文件本身。
- 添加 / 删除会改动压缩包本身,只对 zip、7z、tar 系列可用,其余格式(rar、单文件的 gz / xz 等)按钮置灰。添加放进当前显示的文件夹,同名文件被替换;删除先弹确认,说明会重写压缩包。做法是解压到旁边的临时文件夹、改完重新打包、读一遍校验、再整体替换原文件;任何一步失败或取消,原压缩包原样不动。代价:需要有相当于解压后大小的空闲空间,压缩级别和方法改用设置里的默认值,不保留原压缩包的特殊参数。
- 预览:把选中的单个文件解到系统临时目录,用系统默认程序打开(不超过 256 MB)。程序和脚本(exe、bat、sh、app、js、py 等)一律不打开,提示解压后自行处理,以免预览变成运行。临时文件在系统清理临时目录时删除。
- 文字:基准 13;文件名 13;表头 12;状态栏 12;分组小标题 11;弹窗标题 15–16;欢迎页标题 22。数字、大小、时间用等宽 12。
- 尺寸:工具栏高 46,面包屑 36,状态栏 34,表格行高 28。工具栏按钮和搜索框用常规大小,表格内、面包屑和任务面板里的小按钮用小号。
- 工具栏每个按钮前带线性图标(解压到…↓、添加 +、测试 ✓、删除 垃圾桶(红色)、预览 眼睛)。
- 欢迎页:64 图标块 + 28 标题 + 提示行,"打开压缩包"(主)和"新建压缩"各占一行,宽 360、高 44、字 15;最近打开同宽。两个按钮不并排。
- 设置:工具栏和欢迎页右上角的齿轮、菜单"设置…"、`⌘ ,` 打开浮层。含外观(跟随系统/浅/深)、文件已存在时(询问/跳过/覆盖)、智能解压、自动检查更新、匿名安装统计;改动立即保存。选了固定浅色或深色后,系统切换不再覆盖。
- 首次启动弹"关于匿名统计"浮层,说明上报哪些、不收集哪些;"好的"保留统计,"不参与"关闭,只弹一次。
- 多选:⌘/Ctrl-点击切换单项,Shift-点击选一段;选中行用 `accent-soft` 底。"解压所选"解压所有选中项,详情栏显示"已选 N 项"。翻页或搜索后清空。
- 窗口宽度小于 760 时详情栏自动隐藏。修改时间按本机时区显示。
- 经验:第一版(基准 16、行高 30、工具栏 52)偏大,第二版(基准 12、行高 26、工具栏 42)偏小,现在取两者之间。改尺寸前先用 `screenshots` 示例出图对照。

### 新建压缩

单列面板(最大宽度约 780):已选项目芯片 → 文件名与格式 → 预设三选一 → 高级项(字典、分卷、线程、密码)→ 开关项 → 底部预计体积与用时、取消与开始。

- 预设:极速 / 均衡(默认)/ 最小体积,选中态用强调色边框和浅底。
- 预计体积和用时随预设、线程数实时更新。
- 开关项每项带一行说明,说明讲清后果。

### 任务

任务列表:图标、名称、类型说明、暂停、取消、进度条、已处理量、速度、剩余时间。完成后用深色提示条显示结果和"打开文件夹"。

## 6. 组件规则

- **主按钮**:强调色填充,文字用 `accent-ink`。同一区域只放一个。
- **次按钮**:透明底,悬停显示 `hover`;需要边框时用 `line` 描边。
- **危险按钮**:文字用 `danger`,不做大面积红底。
- **输入框**:`line` 边框,聚焦时 2px `accent` 轮廓。
- **文件类型图标**:圆角小方块加扩展名缩写,文件夹用强调浅底,图片 / 文档 / 代码 / 二进制各用一个固定色相,不引入新的强调色。
- **选中行**:`accent-soft` 底;悬停行:`hover` 底。
- **进度条**:6px 高、全圆角,`accent` 填充。
- **开关**:36×22,开启为 `accent`。
- **加密标记**:用锁图标,不用文字。
- 图标:线性风格,1.7 描边,16px,圆头圆角。

## 7. 交互规则

- 所有主要操作都有键盘快捷键,并在界面可发现(如搜索框显示 `Ctrl F`,macOS 显示 `⌘ F`)。
- 键盘焦点必须可见。
- 拖拽:文件拖入窗口 = 添加;压缩包拖到文件夹 = 解压。
- 危险操作(删除、覆盖)需要确认;可撤销的不弹确认。
- 错误提示说清原因和解决办法,不道歉,不用含糊措辞。
- 文案:动词开头、具体,如"解压到…""开始压缩""打开文件夹"。
- 动效克制:只用于状态过渡(开关、进度),时长不超过 200ms;尊重系统"减少动态效果"设置。
- 无障碍:接入 AccessKit(或框架等价能力),所有控件有可读名称;文字对比度不低于 WCAG AA。

## 8. 平台差异

- 视觉稿未画各系统的原生窗口按钮。窗口标题栏的具体做法(自绘或系统原生)在 UI 框架定案后决定。
- 快捷键、菜单位置遵循各平台惯例(macOS 菜单栏、Windows / Linux 窗口内菜单)。
- 文案支持多语言,不得把中文写死在代码里;使用资源文件。
