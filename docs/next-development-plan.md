# RustZIP 下一步开发盘点与计划

盘点日期：2026-10-25。评估对象是当前工作树中的桌面应用、CLI、归档核心和发布相关能力；初始盘点纳入当时已有的未提交改动。后续已逐项实现 LZ4、ZIP / 7z 分卷、SHA-256 / BLAKE3 哈希、7z 高级压缩、有限大小文本预览，以及 ISO / CAB / CPIO / AR 首批只读后端；验收证据记录在功能状态表中。

## 1. 结论

RustZIP 已有可用的归档核心和桌面主流程：ZIP、7z、tar 系列和 gzip / xz / zstd / bzip2 / LZ4 单文件流读写，首批 ISO / CAB / CPIO / AR 只读后端，ZIP / 7z 分卷、文件哈希、7z 高级参数、有限文本预览，以及转换和修复均已接入。当前主要缺口是其他长尾格式、PDF / 音视频预览、若干 P1 工作流，以及 Windows / Linux 原生 GUI、系统集成与打包的完整验收；分卷外部工具互通也待完成。

四个曾经占位的侧栏功能——常用位置、密码本、格式转换、压缩包修复——在当前代码中已经实现，不能继续列为“未开发”。转换与修复的符号链接和损坏数据边界见 [侧栏实现记录](sidebar-implementation.md) 与 [决策 D9](decisions.md#d9-左栏工具的数据安全与恢复边界)。

## 3. 分阶段计划

### 阶段 A：跨平台验收与规格收口

1. 完成 GPUI 的 Windows / Linux 中文输入、渲染、启动和长列表验收，补充 Linux GUI CI。
2. 在 Windows、Linux 实机验证钥匙串、文件关联、系统菜单和安装 / 升级产物；对未支持的环境明确标记。
3. 决定自动更新采用“下载后交给安装器”还是“应用内自动应用”，据此修订 `product.md` 或新增决策；在决策明确前不实现回滚路径。
4. 为长尾格式建立格式清单：样本、读写档位、加密 / 多卷情况、许可证与依赖、明确的不支持提示。

**退出条件：** 产品规格和决策一致；三平台已支持能力有逐项证据；CI 和发布工作流不把实验项报告为通过。

1. ~~实现 ZIP 与 7z 分卷容器的创建、识别、读取和缺卷诊断，并提供 GUI / CLI 操作入口。~~ 往返、缺卷、取消、已有卷保护及逐卷发布竞态回滚通过；Linux arm64 中 RustZIP ↔ p7zip 26.02 的 ZIP / 7z 分卷互通通过，Info-ZIP 3.0 split ZIP → RustZIP 也通过；待 Windows/macOS 常用工具矩阵。首版范围和卷命名见决策 D18。

## 4. 贯穿各阶段的验收

- 延续 [稳定性提升计划](testing-stability-plan.md) 与 [S1 执行报告](testing-s1-report.md)：先完成仍待执行的 GUI 可恢复性和跨平台格式 / 系统验收，再做压力、性能与发布产物检查。
- 所有新格式、分卷、转换、修复和编辑都验证取消、损坏输入、路径边界、同名冲突、旧目标保全及临时文件清理。
- 触碰压缩 / 解压热路径时跑基准并与同机基线比较；不能用单次吞吐结果替代正确性。
- 生产遥测服务的部署状态本次未核验；官网 / 统计服务代码在当前工作树中，启用统计地址前按 [发布文档](release.md) 完成生产健康检查和数据库迁移。

## 5. 建议的首批实施顺序

1. 先完成阶段 A 的规格决策和平台验收清单，明确哪些功能能对外宣称已支持。
2. ~~先实现分卷，再实现“邮件分享”预设。~~ 已落地 ZIP / 7z 分卷和 20 MiB 默认邮件分享预设。
3. 并行收口 LZ4 与通用校验和；长尾格式按真实需求和依赖许可分批推进。
4. 再做预览、多语言 / 无障碍、通知与完成动作、系统菜单等 P1 高频体验。

没有为各阶段给出日历工期：长尾格式范围、Windows / Linux 设备与打包环境仍需先确认，当前估时会产生较大偏差。
