# 产品功能需求

RustZIP(产品名,大小写固定;仓库和 crate 名用小写 `rustzip` / `rz-*`)是用 Rust 开发的跨平台压缩管理软件(Windows / macOS / Linux)。目标是极致性能、友好的用户体验、简洁美观的界面和全面的功能。基础功能对标 7-Zip,体验上超越它。

## 1. 产品原则

1. **好用优先,但必须快。** 普通用户是主要对象,性能不够快就谈不上好用。
2. **默认简单,高级项折叠。** 默认只露出常用选项,专业参数放进"高级"。
3. **不丢数据、不出意外。** 压缩和解压遇到问题要明确提示,删除源文件前必须先校验。
4. **GUI 与 CLI 共用同一个核心。** 任何能力都先在核心库实现,再暴露给界面。

## 2. 格式支持分档

"全部格式"按三档承诺,并在文档和界面里公开:

| 档位 | 含义 | 格式 |
|---|---|---|
| 读写 | 可压缩、可解压、可修改 | zip、7z、tar、tar.gz、tar.bz2、tar.xz、tar.zst、tar.lz4、gz、bz2、xz、zst、lz4 |
| 只读 | 只能浏览和解压 | rar(含 rar5)、iso、cab、wim、dmg、cpio、ar、rpm、deb、chm、nsis 等长尾格式 |
| 仅识别 | 能识别并提示,不处理 | 其余无法处理的格式,给出明确提示 |

- RAR 只做只读,不做压缩。
- 格式识别靠文件头魔数,不靠扩展名;支持识别嵌套(如 `.tar.gz` 内的内容)。

## 3. 功能清单

### P0:基础能力(对标 7-Zip)

| 模块 | 功能 |
|---|---|
| 压缩 | 多格式压缩;可调压缩级别、字典大小、线程数、分卷、固实块 |
| 解压 | 全格式解压;选择性解压;同名处理(默认保留两者:已有的不动,新的加序号 `名称 (1)`;可选跳过、覆盖);路径安全保护 |
| 浏览 | 不解压直接浏览压缩包内部;搜索、排序;树形或列表视图;百万级条目不卡 |
| 加密 | ZIP AES-256、7z AES-256;7z 文件名加密;密码错误快速判定 |
| 校验 | CRC32、SHA-256、BLAKE3;压缩包完整性测试 |
| 系统集成 | 文件关联;右键菜单(压缩到…、解压到…、解压到当前文件夹);拖拽 |
| CLI | 与 GUI 共用核心,支持创建、列表、解压、校验、转换、修复和哈希 |

ZIP / 7z 分卷首版使用标准 `.z01 … .zip` 和 `.7z.001 …` 卷名；创建时显式设置卷大小，留空则输出单文件归档。缺卷时拒绝打开归档。

7z 高级压缩支持 LZMA2 字典大小和固实块大小。字典留空时按压缩级别选择并在资源预算不足时自动下调；显式请求超过预算时明确失败。固实块大小留空表示整个归档使用一个固实块，设置正数 MiB 会按最大未压缩块大小分组，设为 0 则每个文件独立编码。ZIP 与 tar 系使用各自支持的压缩参数，不显示 7z 专属选项。

文件校验和通过 `rz h` 或 GUI 文件操作计算 SHA-256 / BLAKE3；读取采用有界缓冲，支持取消和进度。压缩包完整性测试仍通过 `rz t` 独立执行。

压缩预设包含极速、均衡、最小体积、邮件分享和跨平台兼容。邮件分享仅用于 ZIP / 7z，默认按 20 MiB 分卷，用户可以调整分卷大小；跨平台兼容预设使用格式默认权限而不保留源权限，在 7z 中省略 Windows 文件属性。

### P1:体验差异化

- **智能解压**:压缩包只有一个顶层目录时直接解压;有多个顶层项时自动建同名文件夹。
- **预览**:压缩包内直接预览图片、文本、PDF、音视频。
- **压缩包内编辑**:拖入、删除、重命名、原地修改,保存时增量重写。
- **编码自动识别**:自动识别中日韩文件名乱码(GBK、Shift-JIS 等),可手动指定。
- **密码管理**:密码本、常用密码自动尝试、系统钥匙串集成。
- **后台任务队列**:多任务并发、暂停和恢复、进度和剩余时间、系统通知、完成后动作(打开文件夹、关机)。
- **任务记录**:已结束的任务(成功、失败、取消)保存在本地,左栏菜单用角标提示进行中、未看的失败和完成数量,重启和升级后保留。
- **压缩预设**:极速 / 均衡(默认)/ 最小体积;另有"邮件分享"(ZIP / 7z 默认 20 MiB 分卷)和"跨平台兼容"(UTF-8 文件名、不保留源权限)。
- **压缩包修复**:损坏的 zip / 7z 尽量恢复可读文件。
- **格式转换**:如 rar 转 7z、zip 转 tar.zst,流式转换不落盘。
- **重复文件检测**:压缩前按内容哈希提示相同文件；最多检查 100,000 个普通文件，超过上限时允许继续但说明未完成检查。用户确认后保留全部输入。自动去重作为独立选项后续评估。
- 深色模式、多语言(简体中文、English、西班牙语、法语、德语、日语、韩语、阿拉伯语、葡萄牙语、俄语)、无障碍。

当前只读长尾格式包括 ISO 9660、CAB、CPIO、AR、LHA / LZH 和 XAR；DEB 包使用 AR 容器识别。仍未接入的承诺格式为 WIM、DMG、CHM、NSIS 等，打开时会给出不支持提示。libarchive 后端通过隔离的 `rz-ffi` 注册显式验收过的格式，不注册 RAR。

当前侧栏增强能力已实现：常用位置、密码本管理、八种目标归档格式的流式转换，以及 ZIP / 7z 尽力恢复。恢复按可读条目另存新包，严重损坏的头部、固实块，以及中央目录丢失后的加密 / 数据描述符 / ZIP64 条目可能无法恢复；结果明确报告。转换暂不保留符号链接，遇到时拒绝；修复会报告跳过。具体边界和验证记录见 `sidebar-implementation.md`。

设置中可选择解压完成后显示结果目录，并单独开启系统通知。通知默认关闭，且只显示通用成功 / 失败信息，不包含文件名和路径。

当前应用内预览支持有限大小的图片和 UTF-8 纯文本（含常见文档、源码和配置格式）。文本按原样显示，不进入 HTML 或脚本渲染；PDF 原生渲染需先解决解压后资源上限，当前 PDF、音频和视频仍交给系统程序打开。

## 4. 自动更新

- 应用内检查更新,后台下载,下次启动时应用。
- 更新包用 Ed25519 / minisign 签名,客户端校验通过后才替换。
- 发布源:GitHub Releases 加 CDN。
- Windows 走 MSIX 或安装器内更新;macOS 可集成 Sparkle;Linux 的包管理器版本只提示不自更新。
- 更新失败必须能回滚,不得导致应用无法启动。

## 5. 安装统计(轻量遥测)

目标只是知道"多少人下载、多少人激活、多少人活跃",**不建用户体系**。

- 首次启动生成随机匿名 UUID。
- 只上报:UUID、软件版本、操作系统及版本、CPU 架构、界面语言。
- 事件:首次启动(激活)、周期性心跳(活跃)。下载数来自 GitHub / CDN 的统计。
- **不收集**:用户名、文件名、路径、文件内容、使用行为。服务端不存 IP。
- 首次启动要明确告知,设置里提供关闭开关,隐私说明写清楚内容。
- 上报失败直接丢弃,不重试风暴,不阻塞启动,不影响使用。
- 接收接口兼容现有 7 字段协议,只接受激活和每日心跳;实现、字段校验与数据库边界见 [`web/`](../web/) 和 [`web/README.md`](../web/README.md)。
