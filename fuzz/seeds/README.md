# Reviewed fuzz seed corpora

The nightly fuzz workflow copies these reviewed inputs into per-target persistent corpora before each run. Generated mutations and crashes stay in ignored `fuzz/corpus/` and `fuzz/artifacts/` directories, then the workflow caches the corpus and uploads failure artifacts.

- `zip_recovery/`: minimal valid, truncated, and missing-central-directory ZIPs built for RustZIP's recovery target.
- `bzip2/seed.bz2`: a small valid stream generated from `docs/product.md` with `cargo run -p rz -- a fuzz/corpus/bzip2/seed.bz2 docs/product.md`; it exercises block and checksum parsing.
- `chm/chm_basic.chm`: RustZIP's bounded LZX fixture, generated by MIT-licensed `rustchm` 0.1.2 and described in `crates/rz-formats/tests/fixtures/README.md`.
- `rar/container.rar`: the 87-byte BSD-2-Clause Homebrew test fixture used by `crates/rz-engine/tests/rar.rs`.
- `nsis` uses `fuzz/make_nsis_seed.py` to generate a synthetic PE overlay with a valid 28-byte FirstHeader signature. It contains no executable code and tests only bounded content identification, not NSIS extraction.
- `pdf_parser` uses `fuzz/make_pdf_seed.py` to generate a minimal one-page PDF; the target exercises Hayro's PDF object and page-tree parsing with a 16 MiB input cap.
- `audio_decoder` uses `fuzz/make_wav_seed.py` to generate a short silent PCM WAV and includes the zero-rate, offset-RIFF, and stacked MPEG/WAV crash inputs. The newest minimized crash combined a truncated MPEG frame with repeated WAV `fmt` chunks and triggered integer overflow in Symphonia 0.6.1. The target exercises supported demux / decoder paths with an 8 MiB input cap and a bounded sample count.
- `video_decoder` copies 64×64, two-frame MP4 and QuickTime/H.264 clips generated from a solid color pattern plus a minimized malformed MP4 that previously stalled nested box parsing. The target exercises bounded container parsing and first-keyframe rendering with a 16 MiB input cap.
